# Verification

The standalone arm64 release APK was rebuilt with Expo Audio and installed on the disposable API 37 emulator. On the previous emulator session, the existing first-collection Maestro flow passed. A seven-second recording reached the draft-ready state, played, saved to SQLite, played from term details, and remained available after an application restart. The backup preparation and Android share sheet showed one recording. The first recording attempt revealed an extended-size MPEG-4 media box; the parser was corrected and the successful capture used that correction.

The emulator cold boot displayed a System UI not responding dialog. After dismissing it, the first-collection, pronunciation recording/playback and microphone-denial Maestro flows passed on the disposable emulator. Permission denial retained the draft. An exported version 2 backup containing a seven-second Android recording was restored through the native document picker on the standard release APK. Playback became available afterward. The file was obtained from a temporary debuggable build on the disposable emulator, then restored on the normal release build. The emulator was in airplane mode during cold start, recording, backup preparation, restore, and playback control checks. The emulator was started with audio disabled, so it cannot establish audibility.

The local Jest suite passed 93 tests across 29 suites, including collection ownership and transactional clip storage, draft recovery after a failed save, version 2 graph validation, a SQLite backup byte round trip, version 1 replacement, and rollback on an audio insert failure. Lint, typecheck, format check and strict OpenSpec validation passed. Expo's online dependency compatibility check reported newer recommended versions for existing packages; it did not flag expo-audio.

Additional Stitch states were generated, with correction frames for discard and oversized backup errors. The extra light and dark PNG/HTML exports are synchronized in gallery screens 61–66. Screen references are in stitch-handoff.md.

The standard release build passed the pronunciation-restore Maestro flow using the exported Android clip while airplane mode was enabled. The recording's container duration was 6966 ms and its payload was 43,939 bytes. Microphone denial and background interruption retained the draft or previous clip on the disposable emulator. Term details playback was also exercised in dark mode at 320 dp width and 200% font scaling. The screen scrolls at large text sizes; the shared native full-width secondary button and text duration are retained as adaptations from the more compact reference. Light and dark details frames were corrected to remove generated phonetic metadata and a decorative waveform.

The emulator used `-no-audio`, so its checks verify playback state transitions and data persistence, but do not establish audibility. On a Pixel 8 Pro running Android 17, the user confirmed audible playback in an isolated test installation. They found that short manual recordings failed; after changing capture validation to read the duration from the audio container instead of finalization wall-clock time, they confirmed that a short spoken word recorded and played clearly. Hosted CI has not been run.

Recording and failure states 55 and 58 were revised in Stitch to remove the extra audio actions, and their paired exports were refreshed.

The rebuilt standard release passed the existing form-guards flow and the updated pronunciation flow on the disposable emulator.
