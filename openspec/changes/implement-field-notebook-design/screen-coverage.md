## Review dimensions

- At the reference size, review all 53 states in both appearances and record captures/evidence in `verification.md` during implementation.
- Review English/Spanish labels, plurals and expansion across the workflows. Exercise representative long forms, filters and file sheets at 320 dp width and 200% font scaling with the keyboard open.
- Verify TalkBack names, type/selection cues, first-error focus, overlay focus containment/restoration and Android Back ordering. Test system appearance changes without draft loss.
- Use real local file generation/picking/sharing and a standalone build in airplane mode for successful file workflows. Recovery-only visual states can use explicitly recorded development/test fault fixtures in an isolated database; keep them out of the shipping app.
- Keep example dates/counts out of production logic. No alias/phonetic/PDF-preview elements can pass acceptance merely because an older source image contained them.

## Additional states without separate artboards

Existing behavior also requires startup/font/database recovery, list loading/read failures, save/delete failures, canceled native file choosers, PDF generation/share failures, missing prepared files and post-commit restore-refresh failure. Exercise these through the shared components and feature-controller tests plus targeted Android checks; do not confuse a mock/fault screenshot with a successful real storage operation.

## Completion rule

A row is reviewed only after the intended native view exists, its primary navigation/interaction works, both appearances have been inspected and the evidence/limitations are recorded. Apply the corresponding implementation tasks and final review tasks 10.4–10.10; the existence of this table or a passing source test alone is not completion.
