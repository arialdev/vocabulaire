## Project

Vocabulaire is an offline vocabulary notebook built with TypeScript, React Native, Expo and Expo Router. Android is the acceptance platform; iOS and web are not supported releases. Persistence uses Expo SQLite and Drizzle. The interface supports English and Spanish, plus system/light/dark appearance.

## Repository map

- `src/app/`: Expo Router routes and application bootstrap.
- `src/features/`: workflow components for vocabulary, onboarding and export.
- `src/ui/`: shared native controls, layout, typography, themes and design tokens.
- `src/data/`: database initialization, schema, repository and service providers.
- `src/domain/`: vocabulary query and daily-word rules.
- `src/platform/`: backup/PDF generation and native file/share integrations.
- `src/i18n/`: interface translations and locale setup.
- `modules/emoji-picker/`: app-owned Expo module with an Android Jetpack picker.
- `drizzle/`: tracked SQL migrations and metadata.
- `__tests__/` and `test-support/`: Jest tests, native database support and fixtures.
- `.maestro/`: Android interaction and visual-review flows.
- `design/vocabulaire/`: Stitch design handoff, screen inventory, exports and review gallery.
- `openspec/`: behavior specifications and change proposals, tasks and verification evidence.

## Implementation conventions

- Use strict TypeScript and the existing route, feature, repository and platform boundaries. Keep database operations and file/share logic out of presentation components.
- Reuse `src/ui/` controls, semantic tokens, typography and theme hooks. Bundle required fonts/assets so the app works offline.
- Add user-facing copy and accessibility labels to both interface languages in `src/i18n/`. Vocabulary content can use any language; preserve Unicode, multiline text and script fallbacks.
- Follow the design's accessibility requirements: 48 dp touch targets, readable contrast, text scaling to 200%, narrow layouts, safe areas, keyboard clearance, reduced motion and Android Back/focus behavior.
- Preserve form drafts on cancellation or failed writes. Keep destructive confirmations, duplicate-action guards and recoverable error behavior consistent with shared components.
- Preserve collection-scoped data integrity, transactional writes and supported backup round trips. The collection short label is hidden in the UI but existing values must survive edits and backups.
- Consult `BACKUP-FORMAT.md` before changing portability behavior. Legacy Ionic backups are unsupported; restoring a supported backup replaces the current dataset.
- Change the schema in `src/data/schema.ts` and generate migrations with `mise exec -- pnpm db:generate`; keep SQL and migration metadata consistent.
- Keep native source changes in app configuration and `modules/`. The ignored `android/` and `ios/` directories are generated by Expo prebuild and may be replaced.
- Treat `.legacy/`, old Ionic/Cypress material and historical source as reference. Use the current React Native tests and Android acceptance flows.
- Consult relevant OpenSpec specs and active change tasks before implementation. Keep affected specs, tasks and evidence accurate; check tasks off only after completing the work and verification.

## Setup and commands

Use the tool versions pinned in `mise.toml` and the pnpm lockfile. See `README.md` and `COMPATIBILITY.md` for Android SDK setup and dependency constraints.

```sh
mise install
mise exec -- pnpm install --frozen-lockfile

# Generate and install the Android development build.
mise exec -- pnpm exec expo prebuild --platform android --no-install
mise exec -- pnpm android
mise exec -- pnpm start --dev-client
```

The native emoji picker requires a development build; Expo Go cannot load it.

Run the checks appropriate to the change. For application changes, the core checks are:

```sh
mise exec -- pnpm lint
mise exec -- pnpm format:check
mise exec -- pnpm typecheck
mise exec -- pnpm test --runInBand
```

Use `mise exec -- pnpm format` to apply the repository formatter. For dependency changes, also run `mise exec -- pnpm exec expo install --check` and consult the accepted compatibility warnings. CI configuration is in `.github/workflows/pipeline.yml`.

## Verification

- Add or update focused Jest coverage for changed behavior, using React Native Testing Library for component interactions and existing database/fixture helpers for persistence.
- For UI or native changes, run the affected Maestro flows on an Android emulator/device with the appropriate APK installed. Use a standalone build for offline cold-start and native file/share acceptance; see `README.md` for build commands.
- Maestro flows can clear application data and restore fixtures. Run them only on a disposable test device or emulator.
- Keep `EXPO_PUBLIC_NOTEBOOK_REVIEW_FAULTS` unset or `0` in normal builds. Its review-only controls must never ship.
- Report which checks ran, their results and any remaining verification limits. Distinguish local emulator results from physical-device and hosted CI results.
